# Changelog – XCX Web Interpreter v2.0.0

## [2.0.0] - 2026-07-13

### Fixed
- **Expressions**: Fixed double evaluation of operands for the `+` operator in the string concatenation fallback path.
- **Tables**: Avoided type mismatches in `table.update` by using the defined column type to wrap updated values rather than guessing based on JS raw types.
- **Arrays**: Added support for wrapping `"table"` element types inside `wrapElement`, fixing `RuntimeError: Unsupported wrapping type 'table'` when calling `.get()` on rows array from `.rows()`.
- **Parser**: Demoted `data` and `schema` from reserved keywords to contextual identifiers, allowing their use as variable names (e.g. `json: data = ...`) without breaking table or map declarations.

### Performance & Optimizations
- **Loops JIT Compiler**: Implemented a modular JIT compilations compiler under a new module (`jit.ts`) that transpiles AST loops (`for`/`while`) into native JavaScript executable functions (`new Function(...)`). This bypasses recursive AST traversals in hot execution loops, improving performance up to **250x** (1 billion loop count finishes in ~700ms).
- **Environment**: Reused `Environment` instances inside `table.where` and `table.join` iteration loops, avoiding expensive allocation of a child environment per row.
- **Tables**: Implemented $O(N + M)$ hash join algorithm for key-based table inner joins instead of a nested loop of complexity $O(N \times M)$.
- **Include**: Cached parsed Abstract Syntax Trees (AST) in the `Interpreter` instance, preventing redundant tokenizer parsing for multiple includes.
- **Delay**: Substituted CPU-intensive busy-loop wait in `evalWait` with `Atomics.wait` if `SharedArrayBuffer` is supported to prevent 100% CPU thread starvation.

### Dead Script & Miscellaneous Cleanup
- **Jest**: Replaced dead Jest command in `package.json` test script with `npm run runner` since the test suite runs on native `.xcx` files.
- **Error Handling**: Removed redundancy in the `RuntimeError` class constructor inheritances.
